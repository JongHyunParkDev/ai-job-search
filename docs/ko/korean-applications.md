# 한국 지원서 작성 가이드 (ko-market)

`/apply`와 `08-application-forms.md`를 한국 채용에 쓸 때 실제로 부딪히는 관행을 모은 문서입니다. 원본 프레임워크의 원칙(모든 주장은 프로필·마스터 CV에 근거해야 한다)은 그대로 적용하고, 그 위에 한국 지원서에서만 생기는 문제를 다룹니다. 내용은 2026년 10월 실제 지원 서류를 만들면서 확인한 것입니다.

## 1. 서류 구성

| 서류 | 형태 | 비고 |
|---|---|---|
| 이력서 | 자율양식(파일 첨부) 또는 회사 양식(웹 입력) | IT 경력직은 자율양식이 많습니다 |
| 자기소개서 | 문항별 웹 입력, 문항마다 글자 수 제한 | 대기업·중견은 거의 필수입니다 |
| 경력기술서 | 자율양식, 프로젝트 중심 | 이력서와 합쳐 내는 경우가 많습니다 |

포털(사람인·잡코리아 등)에서 바로 지원하는 공고와, 공고만 포털에 걸고 **회사 채용 사이트에서 지원**하게 하는 공고가 있습니다. 대기업·중견 대부분은 뒤쪽입니다(8장).

## 2. 자율양식 이력서

- **첫 쪽에 "공고 요구사항 대응표"를 둡니다.** 왼쪽에 공고의 필수·우대 항목, 오른쪽에 그 항목을 뒷받침하는 실제 경험을 한 줄씩 적습니다. 서류 검토자가 요건 충족 여부를 바로 확인할 수 있습니다.
- 대응표의 근거는 마스터 CV에 있는 사실만 씁니다. 경험이 없는 항목(예: Kubernetes 실무)은 표에서 빼거나 "실무 미사용"이라고 정직하게 적습니다.
- 공고마다 **프로젝트 순서**를 바꿉니다. 사실은 같고, 공고와 가장 관련 있는 프로젝트를 앞에 둡니다.
- 분량은 A4 3쪽 이내를 권합니다.

## 3. 한국 이력서에서 자주 틀리는 부분

- **생년월일·나이·사진·상세 주소:** 블라인드 채용이 늘어 생략해도 됩니다. 공고가 요구하면 따릅니다.
- **경력 기간 계산:** 입사월부터 퇴사월까지 개월 수로 셉니다(예: 2020.02 ~ 2025.05 = 63개월 = 5년 3개월). 총 경력은 회사별 기간의 합이며, 같은 달에 이직했다면 겹치는 달을 두 번 세지 않습니다. 원본 이력서의 계산이 틀린 경우가 많으니 다시 계산합니다.
- **퇴사한 회사의 "진행 중" 프로젝트:** 퇴사 월로 종료 처리합니다. 그대로 두면 재직 중으로 오해받습니다.
- **프리랜서 경력:** "소속사 · 프리랜서 (고객사 프로젝트)" 형태로 적습니다. 공고가 "재직 경력이 아닌 직무 경험 기간"을 요구하면(예: 직무경험 3~8년) 프리랜서 기간도 포함해 회사별로 나눠 적습니다.
- **기여도 %:** 30% 같은 낮은 수치는 오히려 불리하게 읽힙니다. 팀 규모와 본인 역할로 바꿔 적습니다.
- **기술 스택에만 있고 프로젝트 설명에는 없는 기술:** "사용 경험" 정도로 표현을 낮춥니다. 면접에서 그 기술을 어디서 썼는지 질문받습니다.
- **연차 요건 미달:** 반올림하지 않습니다(6년 8개월 ≠ 7년). "또는 그에 준하는 역량" 같은 대체 조건이 있는지 공고를 다시 읽습니다.

## 4. 자기소개서 문항 패턴

경력직 자기소개서는 아래 문항이 반복됩니다. 같은 경력으로 회사별 답변을 만들 때는 1·2번만 새로 쓰고 3~5번은 회사명과 강조점만 바꿔도 됩니다.

| 문항 | 쓸 내용 | 주의 |
|---|---|---|
| 지원 동기(회사·직무) | 지금 하는 일이 그 회사의 일과 어떻게 이어지는지 | 회사 서비스 이야기는 실제로 써 본 경험만 씁니다. 회사와 서비스의 관계(직접 개발인지, 그룹 계열인지)를 확인하지 못했으면 "그룹 계열"까지만 씁니다 |
| 차별화된 역량 | 수치가 있는 성과 2~3개 | 형용사보다 상황과 숫자를 씁니다 |
| 회사별 직무 경력 | 회사·기간·역할·대표 성과를 목록으로 | 직무 경험 기간 합계를 첫 줄에 적습니다 |
| AI 활용 | 도구 이름, 적용 방식, 성과, 검증 방법 | 최근 늘어난 문항입니다. "체감" 수치는 체감이라고 밝힙니다 |
| 자유양식 | 공백기, 퇴사 사유, 근무지 가능 여부 | 퇴사 사유에 전 직장 평가("조직이 정체되어 있다" 등)를 쓰지 않습니다. 사실과 그다음 행동만 씁니다 |
| 성장 과정 · 입사 후 포부 | 대기업 공채 전통 문항 | 포부는 단계별(입사 직후 → 1년 → 3년)로 씁니다 |

## 5. 글자 수 검사

포털마다 글자를 세는 방식이 다릅니다. 공백 포함·제외 여부, 줄바꿈을 1자로 셀지 2자로 셀지, CP949 바이트 단위인지가 다르고, 빈 줄(연속 줄바꿈)을 쓰지 말라는 포털도 있습니다. 추측하지 말고 도구로 셉니다.

```bash
python3 tools/ko_char_count.py --in answers.txt --limit 1000
python3 tools/ko_char_count.py --in answers.txt --limit 1000 --mode nospace --no-blank-lines
```

입력 파일 형식: 답변마다 첫 줄에 `# 문항 제목`을 쓰고(세지 않음), 답변 사이는 `---` 한 줄로 나눕니다. 답변 본문 안에는 `---`만 있는 줄을 쓰지 마세요(구분선으로 읽힙니다). CP949 바이트로 제한하면서 줄바꿈을 2바이트로 세는 포털은 `--mode cp949_crlf`를 씁니다. 붙여 넣은 뒤 포털이 보여 주는 글자 수와 한 번 더 비교합니다.

## 6. 연봉 처우 협의

- 서류 단계의 희망 연봉 칸은 **"회사 내규에 따름" 또는 "협의"**로 둡니다.
- 한국 기업은 보통 **직전 정규직 연봉**을 기준으로 인상률을 정합니다. 근로소득 원천징수영수증을 요구하는 경우가 많습니다.
- **프리랜서 소득을 정규직 연봉으로 환산할 때:** 회사가 정규직 한 명에게 쓰는 비용은 대략 연봉 × 1.18입니다(퇴직금 약 8.3% + 사업주 부담 4대보험 약 9.5%). 따라서 프리랜서 연 수입 ÷ 1.18 정도가 손익이 비슷해지는 연봉입니다. 예를 들어 프리랜서 수입이 월 500만 원(연 6,000만 원)이면 약 5,080만 원입니다. 비율은 해마다 바뀌는 보험료율에 따라 달라지는 어림값입니다.
- 프리랜서 기간 소득을 인정받으려면 사업소득 원천징수영수증과 계약서를 준비합니다.

## 7. 제출 파일 함정: 사내 문서보안(DRM)

회사 PC에 문서보안 프로그램(DRM)이 깔려 있으면, Word·한글 같은 오피스 프로그램으로 저장하거나 PDF로 내보낸 파일이 **자동으로 암호화**됩니다. 이런 파일은 회사 밖(채용 담당자 PC)에서 열리지 않습니다. 2026년 10월 실제로 Word에서 내보낸 PDF가 `%PDF-`가 아니라 보안 프로그램의 헤더로 시작하는 것을 확인했습니다.

- **확인:** PDF는 첫 5바이트가 `%PDF-`, docx는 첫 2바이트가 `PK`여야 합니다.
  ```bash
  python3 -c "import sys; print(open(sys.argv[1],'rb').read(5))" 이력서.pdf
  ```
- **해결:** 문서보안이 걸리지 않는 프로그램(예: LibreOffice `soffice --headless --convert-to pdf`)으로 PDF를 만들거나, 다른 PC에서 열리는지 확인한 뒤 제출합니다.
